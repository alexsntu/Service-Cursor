# Повторный аудит dev.irepair.ru

6 сентября 2026, около 20:26–20:28 МСК. Прочитана обновлённая память Claude Code. Проверки выполнены по SSH и HTTP; конфигурации сервера не изменялись.

**Вывод: три существенных исправления подтверждены. Базовое окружение подходит для продолжения разработки CS-Cart. Все замечания пока не закрыты.**

## Исправлено

- **Выдача .htaccess и шаблонов:** оба ранее доступных URL теперь возвращают 404, в том числе при повторном запросе. Включены запреты dotfiles и `.tpl`.
- **Доступ к dev и индексация:** главная возвращает 401 с Basic Auth. robots.txt на диске содержит `Disallow: /`. Сам robots.txt тоже требует авторизацию; для закрытого dev это нормально, доступ роботов блокируется раньше.
- **SSH по ключам:** PasswordAuthentication=no, PermitRootLogin=without-password. Подключение существующим ключом работает.

## Конфликт временных каталогов остаётся

Пул сайта задаёт:

```
upload_tmp_dir = /var/www/www-root/data/mod-tmp
session.save_path = /var/www/www-root/data/mod-tmp
open_basedir = /var/www/www-root/data/dev.irepair.ru:/tmp:/var/lib/php/sessions
```

`readlink -f` подтвердил, что mod-tmp не является ссылкой на /tmp. Проверка PHP CLI от пользователя www-root с тем же open_basedir дала `open_basedir restriction in effect` и false для mod-tmp, true для /tmp. Файлы не создавались. Это подтверждает конфликт путей; конкретный сбой загрузки через живой FPM/админку не воспроизводился. Фактические сессии CS-Cart хранятся в БД.

Вывод в памяти «не проблема, потому что /tmp разрешён» ошибочен: настроена другая папка. Нужно разрешить точный mod-tmp либо изменить временную папку на подходящую разрешённую; затем проверить загрузку изображения и архива модуля. Не требуется снимать open_basedir целиком.

## Защита Nginx исправлена частично

`/app/addons/ab__addons_manager/addon.xml` теперь даёт 401, то есть скрыт Basic Auth. Однако отдельных правил защиты app/var/backups и запрета PHP в загрузках в активной конфигурации по-прежнему нет. После снятия Basic Auth перед запуском часть защиты исчезнет. Добавить правила CS-Cart с исключениями для публичной статики и точек входа модулей; не закрывать весь var без разбора. Запрос с авторизацией не выполнялся; вывод основан на конфигурации и неавторизованном ответе.

## Что остаётся открытым

- **DNS/HTTPS:** авторитетный ns1.reg.ru не возвращает A; 443 не слушается. Нужны A-запись и сертификат. Basic Auth до HTTPS не шифрует передаваемые реквизиты.
- **Сетевой доступ:** UFW inactive; iptables INPUT ACCEPT с цепочками ISPmanager. FTP 21, DNS 53 и панели 1500/1501 слушают внешние интерфейсы. Внешний firewall Beget не проверялся. Не включать второй firewall вслепую поверх панели.
- **Панель 1501:** конфигурация всё ещё допускает TLS 1.0/1.1. Ограничить современными протоколами и проверить совместимость панели.
- **Обновления:** по существующему индексу APT остаются 192 обновляемых пакета. Индекс не обновлялся. Нужен снимок и плановое обновление совместимых версий.
- **Бэкапы:** в var/backups сайта только .htaccess; внешний бэкап и восстановление не подтверждены. Это не доказательство отсутствия копий в Beget/ISPmanager.
- **Redis:** cache_backend=file, session_backend=database. Redis maxmemory=0, noeviction. Подключение кэша и бюджет памяти ещё не настроены.
- **Долгие операции и формы:** PHP 300 с, fastcgi_read_timeout явно не задан (стандарт Nginx — 60 с между чтениями); max_input_vars=1000. Проверить операции установки/импорта и большие формы темы.
- **Сжатие и наблюдаемость:** gzip выключен; FPM slowlog/status не настроены; MySQL slow_query_log=OFF.
- **Права:** config.local.php остаётся 666. Сужать права с учётом пользователя FPM и обновлений CS-Cart.
- **Планировщик:** в просмотренных каталогах нет нового задания сайта; необходимость и команды определять по установленным модулям, не предполагать наличие универсального cron CS-Cart.

## Ресурсы и базовые настройки

Доступно 10 601 MiB из 11 960 MiB памяти, swap 4 GiB не занят. Диск заполнен на 7%, около 136 GiB свободно. Упавших systemd-служб нет. Синтаксис FPM корректен. Сохранились 30 процессов пула, memory_limit=256M, upload=64M, post=72M; OPcache 256 MiB/30000; MySQL buffer pool 3 GiB и 100 соединений. Увеличивать ресурсы пока оснований нет.

Новая проверка не включает нагрузочный тест, вход в админку, установку темы, SMTP и восстановление копий. После Basic Auth проверяется защита доступа, а не работа витрины за авторизацией. Совместимость базового окружения установлена в первом аудите; установленный набор расширений повторно полностью не перечислялся.
