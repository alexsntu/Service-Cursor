## 3. Общие правила разработки

1. **Блоки вставляет владелец сам.** Код готовим в файлах проекта и говорим, в какой блок и какую категорию его вставить.
   Сами в пользовательские блоки CS-Cart (190, 202, 205 и др.) не пишем. Шаблоны, аддон, файлы на сервере,
   CSS темы, данные через API/SQL — можно, но всегда сообщаем, что поменяли.
2. **Изоляция стилей.** У каждого компонента свой корневой класс и свой локальный сброс.
   Стили блоков главной и страниц лежат **внутри своего файла** (`<style>`); в общий `irepair-old-header.css`
   идёт только то, что есть на всех страницах (шапка, подвал, окно заявки, поиск).
3. **Двойной префикс у заголовков:** `.root .root__title` (особенно h1/h2), иначе тема перебивает.
   **Заголовок блока главной — единый формат:** `font-family: 'Montserrat-SemiBold', Arial, sans-serif; font-size: 38px; line-height: 1.15; font-weight: 400; text-transform: none; color: #1d1d1f;`, на телефоне (≤650 px) `font-size: 24px`. Новые блоки делаем так же.
   Для H1 добавляем сбросы: margin/padding 0, font-weight 400, letter-spacing, text-transform.
4. **Ссылки только относительные** (`/catalog/…`, `/images/…`), чтобы переезд dev → irepair.ru ничего не сломал.
   Абсолютные — только внешние сайты (магазин, соцсети, карты).
5. **Никаких эмодзи символами**: база utf8mb3 превращает их в «?». Только HTML-сущности.
6. **LESS в CS-Cart** (общий CSS проходит через него):
   - нельзя `calc()` со смешанными единицами: `calc(100% - 20px)` превращается в мусор;
   - `backdrop-filter: blur() saturate()` пишем через `~"…"`.
7. **Картинки только на нашем сервере** (`/images/content/<раздел>/`), со старого домена не подгружаем.
   Товарные фото обрезаются по контуру; если после обрезки сторона меньше 500 px — фото в списке «заменить потом».
8. **Проверка вёрстки на телефоне:** страница в `<iframe>` шириной 390 px (изменение размера окна не работает).
   Мобильная шапка переключается по ширине ≤1180 px.
9. **В коде «HTML блока с поддержкой Smarty» нельзя писать `{` вплотную к символу** (`{3}`, `{a}`): Smarty считает это своим
   тегом и вырезает. Пример: регулярное выражение `\d{3}` на сайте превратилось в `\d3`, и цена в калькуляторе склеилась.
   Пишем `\d\d\d` или ставим пробел после `{`; большие куски JS можно обернуть в `{literal}…{/literal}`.
   Неразрывный пробел пишем в JS как `\u00a0`, а не символом.
10. У «HTML блока с поддержкой Smarty» защищённый режим: работают только функции из схемы
   `smarty_allowed_functions`. Если нужны данные из базы — пишем функцию в `my_changes/func.php` и разрешаем её в схеме.
11. Ширина контента на всех блоках: `.g-wrapper` (max 1370 px, отступы 35 px, на телефоне 16–20 px).
    Бренд: зелёный `#37d97b` / `#36d97b`, бирюзовый `#19d4e0`, градиент кнопок `linear-gradient(103.87deg, #36d97b 29.3%, #19d4e0 96.89%)`.

**Выкладка общего CSS.**
1. Файл на сервере хранится с переводами строк CRLF. Перед заменой сравнить его с версией в git.
2. Сделать резервную копию `/root/New iRepair.css.bak-<дата>`.
3. Заменить файл.
4. Очистить `var/cache/misc/assets`, `var/cache/registry`, `var/cache/templates`.
5. `UPDATE cscart_storage_data SET data=UNIX_TIMESTAMP() WHERE data_key='cache_id'`, иначе браузеры держат старый CSS.

## 5. Заявки → Bitrix24

- `backend/send-lead.php` → на сервере `/ajax/send-lead.php`. Свой обработчик, **без модулей CS-Cart**.
- Принимает POST: `name`, `phone` (обязателен), `service`, `price`, `uri`, `comment`.
  Шлёт в вебхук Bitrix24 `crm.lead.add`. URL вебхука хранится только в самом php-файле, в браузер не попадает.
- Поля лида: `TITLE` = услуга (или «Заказ звонка»), `COMMENTS` = цена + страница + комментарий,
  `SOURCE_ID=30`, `STAGE_ID=UC_ZR6PTH`, `UF_CRM_METRIKA_CLIENT_ID` (`_ym_uid`).
  Старые поля `UF_CRM_17035…` в Bitrix24 больше не существуют, поэтому пишем в COMMENTS.
- Ошибки пишутся в `ajax/send-lead-errors.log`. Посетитель всегда видит «Спасибо».
- Отправляют сюда: окно заявки из шапки, калькулятор, Trade-in, Доставка, Программа лояльности, карточка услуги,
  прайс категории, «Оставить заявку» из поиска.
- Маска телефона — IMask (как на старом сайте). Антиспама нет, есть только ограничение nginx по IP.

## 7. Калькулятор, прайс и таблица цен

- **Главный источник цен — мастер-таблица** `~/Документы/Сервис/Новая таблица<NNN>.xlsx`, лист «МСервис».
  - E — id услуги в RemOnline;
  - B — ссылка на старый товар (product_id);
  - H — модель;
  - L — гарантия;
  - N — A-номера / размер корпуса / «Модуль»;
  - **AY — текущая цена**.
- `main-page/scripts/build-repair-prices.py` строит `main-page/data/repair-prices.json`.
  На сервере файл лежит в `/images/content/repair-prices/repair-prices.json`, его читают **калькулятор** и страница **«Стоимость услуг»** (`pages/prices.html`).
- Порядок обновления при новом файле таблицы:
  1. Запустить скрипт и прочитать сравнение с прошлой версией (новые и пропавшие модели и услуги).
  2. Разобрать предупреждения ⚠: новый чип MacBook → `CHIP_MAP`; новая модель MacBook → `MACBOOK_MODEL_ORDER` в **трёх** местах (py, калькулятор, prices.html); новая услуга → проверить `CATEGORY_RULES` в prices.html.
  3. Сообщить владельцу, какие модели и услуги появились и пропали.
  4. Залить JSON на сервер.

## 15а. Личный кабинет

Страница `/personal/`. Своя часть, **без модулей и пользователей CS-Cart**. Работает с тремя внешними сервисами:
**RemOnline** (клиенты, заказы), **BonusPlus** (карта лояльности, баллы), **sms.ru** (код входа).
Состояние на 2026-10-06: вся цепочка проверена на тестовом клиенте; **списание и начисление выключены** до переезда.

### Что видит клиент

1. **Вход.** Телефон + **обязательная галочка «Я согласен(на) на обработку персональных данных»** (по умолчанию снята; без неё код не отправляется —
   проверяется и на сервере; дата и адрес согласия записываются клиенту: `consent_at`, `consent_ip`) → проверка, что клиент есть в RemOnline (иначе «Пользователь не найден») → СМС с кодом из 4 цифр → вход на 30 дней.
   Отдельной регистрации на сайте нет: войти может любой клиент сервиса.
2. **Карта лояльности.** Уровень, баллы, «Кешбэк X% · оплата баллами до Y%». Если клиента нет в BonusPlus — карта создаётся автоматически
   (начальный уровень, без СМС о регистрации, без стартовых баллов).
3. **История баллов** (ссылка в блоке карты): начисления и списания с датой; номер заказа — ссылка, раскрывает этот заказ ниже.
4. **Заказы** — сворачиваемые строки: номер, устройство, статус, сумма. При раскрытии: даты приёма и закрытия, стоимость, кешбэк,
   состав заказа с ценами и гарантией. Текущие раскрыты, если их один-два или можно списать баллы; история свёрнута, 5 заказов + «Показать все».
5. **Статусы** клиент видит не служебные из RemOnline, а подпись по группе статуса: «Принят», «В работе», «Ожидает», «Готов», «Доставка», «Выдан», «Закрыт».
   В «Историю» уходят только закрытые заказы (группы 6 и 7); «Готов» остаётся в текущих.
6. **Гарантия** по-русски («6 месяцев», «14 дней»). У закрытого заказа — срок по каждой услуге «с … по …» **от даты закрытия заказа** и пометка «действует» / «истекла».
7. **Личные данные** — сворачиваемый блок в первом ряду рядом с картой, той же высоты (в свёрнутом виде: имя и телефон).
   При раскрытии: имя, фамилия, почта, дата рождения, пол — сохраняются сразу при изменении. Имя клиент может поправить сам:
   оно хранится только в кабинете и **не передаётся в RemOnline и BonusPlus** (пустые имя и фамилия — вернуть имя из RemOnline).
   Расположение: первый ряд — карта и личные данные, второй — «Текущие заказы» и «История заказов» на одном уровне;
   под ними слева «Избранные услуги», справа «Просмотренные услуги».
8. **Избранные услуги** — то же избранное CS-Cart, что на странице `/wishlist/` (сердечко на карточке услуги): фото, название-ссылка, цена, кнопка «убрать».
   Для вошедшего в кабинет избранное **привязано к телефону** (таблица `irepair_lk_favorites`): при открытии кабинета список браузера
   объединяется с сохранённым за клиентом, а дальше каждое изменение (сердечко на карточке, страница `/wishlist/`, крестик в кабинете)
   сразу записывается клиенту — список одинаковый на любом устройстве. Без входа в кабинет избранное по-прежнему только в браузере.
   **Чужое не смешивается:** при выходе из кабинета (и когда вход истёк) избранное клиента убирается из браузера и остаётся только за ним;
   если в браузере остался список другого клиента, при входе он заменяется своим. Избранное, собранное без входа, при входе добавляется клиенту.
9. **Просмотренные услуги** — услуги, которые клиент открывал на сайте (последние первыми, показываются 4 и «Показать все»).
   Сохраняются за клиентом (таблица `irepair_lk_viewed`, последние 50): при открытии кабинета новые просмотры из браузера дописываются клиенту.
   При выходе из кабинета просмотры клиента из браузера тоже убираются.

### Баллы: как устроены списание и начисление

| Шаг | Когда | Что происходит |
|---|---|---|
| Списание | заказ в статусе RemOnline «отправить на скидку. "ГОТОВ"» (48061), клиент нажал «Списать баллы» | скидка на позиции заказа в RemOnline (до процента карты) + списание баллов в BonusPlus. **Продажа в BonusPlus при этом не создаётся** |
| Начисление | заказ закрыт в статус «С \| Успешно (Рем)» или «С \| Успешно (Яндекс)» | `accrue.php` регистрирует в BonusPlus **одну продажу на фактически оплаченную сумму** (после скидки баллами); баллы начисляет сам BonusPlus по проценту карты; сумма покупок растёт → уровень карты повышается сам |

- Проценты задаются **только в BonusPlus**, раздел «Лояльность → Карты»: SILVER 15% / 10%, GOLD 20% / 15% (от 60 000 ₽), PLATINUM 20% / 20% (от 150 000 ₽).
  Акции «Начисление за товар — …» там же перекрывали эти проценты (давали ≈1–2%) — владелец их отключил 2026-10-06. Если кешбэк снова станет не тем, смотреть раздел «Акции».
- RemOnline и BonusPlus между собой **не связаны**: всё, что попадает в BonusPlus, делает сайт.
- Защита списания: одна операция на заказ (`irepair_lk_spend_lock`: pending → done / failed / review). Успех клиенту показывается только после подтверждения BonusPlus;
  нет ясного ответа — сверка по остатку баллов; баллы не списались — скидка в RemOnline снимается и можно повторить; итог неизвестен — «проверяет менеджер».
- Обратной связи нет: если менеджер после списания убрал скидку в RemOnline, баллы клиенту сами не вернутся — правится вручную в BonusPlus.

### Защита

Код из СМС живёт 5 минут и даёт 5 попыток; СМС не чаще раза в минуту, до 4 в час и 8 в сутки на номер, 20 запросов в час с одного адреса;
состав заказа и списание — только по своим заказам; телефон в каждом заказе сверяется (RemOnline на незнакомый фильтр отдаёт заказы всех клиентов);
запросы только со своего сайта; ключи — только в `config.php`. Ошибки пишутся в журнал PHP с пометкой `[irepair-lk]`.
