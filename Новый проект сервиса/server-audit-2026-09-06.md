# Аудит dev.irepair.ru — 6 сентября 2026

Проверка по SSH и HTTP выполнена около 20:10–20:13 МСК. Конфигурации не изменялись; установка пакетов, перезапуски и нагрузочные тесты не выполнялись. HTTP проверялся через IP с Host dev.irepair.ru, поскольку DNS A-запись отсутствует. Проверки HTTP могут создавать обычные записи журналов и сессии приложения.

**Вывод:** базовое окружение подходит для CS-Cart 4.21.1. Ресурсов для продолжения разработки достаточно. Перед публичным открытием нужно исправить защиту Nginx, согласовать временные каталоги PHP, включить HTTPS и закрыть тестовый сайт от индексации. Готовность под реальную нагрузку пока не подтверждена.

- OPcache включён: 256 MiB, max_accelerated_files=30000. Это конфигурация, заполненность работающего кэша не измерялась.

- Nginx и FPM проходят проверку синтаксиса. Главная возвращает HTTP 200. Три последовательных локальных замера TTFB: 149, 148 и 129 мс. Это пустая витрина без реальной нагрузки и без сетевой задержки посетителя.

## Исправить в первую очередь

### 1. Nginx раскрывает служебные файлы — подтверждено

HEAD-запросы возвращают HTTP 200 и размер реального файла для `/.htaccess`, `/app/addons/ab__addons_manager/addon.xml` и `/design/backend/templates/index.tpl`. В конфигурации сайта нет необходимых запретов для служебных каталогов и шаблонов. Nginx не применяет правила .htaccess.

Нужно добавить совместимые с CS-Cart location-правила: закрыть служебные файлы, шаблоны, резервные копии; запретить исполнение PHP в каталогах загрузок; сохранить доступ к нужным CSS/JS/изображениям и предусмотренным точкам входа модулей. Не закрывать весь var без исключений для публичного кэша. После изменения повторить HTTP-проверки и проверить витрину/админку. HTTP 200 у config.local.php сам по себе не доказывает утечку исходника: файл обрабатывается PHP. Скачивание паролей или резервных копий не выполнялось.

### 2. Временный каталог PHP исключён из open_basedir — подтверждён конфликт конфигурации

Пул задаёт upload_tmp_dir и session.save_path как `/var/www/www-root/data/mod-tmp`. Но open_basedir разрешает только корень сайта, `/tmp` и `/var/lib/php/sessions`. Это риск ошибок загрузки модулей, изображений и операций с файловыми сессиями. В просмотренном журнале таких ошибок пока нет; тестовую загрузку не выполняли. Сессии самого CS-Cart сейчас хранятся в БД.

Решение: включить точный временный каталог в разрешённые пути либо перенести временные файлы в разрешённую приватную директорию; затем проверить загрузку через админку. Не отключать ограничение автоматически. PHP также документирует, что open_basedir отключает realpath cache: учитывать это при последующей оценке производительности.

### 3. DNS и HTTPS ещё не готовы — подтверждено

Cloudflare DNS не возвращает A/AAAA. Авторитетный ns1.reg.ru отвечает NOERROR, ANSWER=0 для A. Порт 443 не слушается. Главная доступна по HTTP при принудительном указании IP.

Нужно добавить A-запись, выпустить сертификат, настроить HTTPS сайта и админки, проверить продление и перенаправления. Это также необходимая основа для планируемой PWA. Публичная работа админки по HTTP до этого нежелательна.

### 4. Тестовый сайт не закрыт от индексации — подтверждено

robots.txt запрещает только `/app/` и `/store_closed.html`. На главной нет robots meta и X-Robots-Tag. В конфигурации нет Basic Auth. После появления DNS разработка будет доступна поисковым роботам.

Для dev предпочтительна авторизация на уровне сервера; дополнительно noindex и отдельный robots.txt. Сохранить доступ ACME для сертификата. При переносе на основной домен снять именно ограничения индексации production.

### 5. SSH и сетевой доступ требуют усиления — подтверждено частично

sshd -T показывает PermitRootLogin=yes и PasswordAuthentication=yes, включая проверенный контекст root. Успешно подключились ключом проекта, однако режим «только по ключу» из памяти не настроен. Fail2ban защищает только sshd. UFW неактивен; iptables имеет политику INPUT ACCEPT и цепочки ISPmanager, общего запрета входящих соединений нет.

На внешних интерфейсах слушают SSH 22, FTP 21, DNS 53, панели 1500/1501 и HTTP 80. Это проверка прослушивания и локальных правил, а не доказательство доступности каждого порта извне: firewall Beget не проверялся.

После проверки резервного доступа отключить парольный SSH-вход, ограничить панели доверенными адресами/VPN, определить необходимость FTP/BIND. Менять firewall через совместимый с ISPmanager механизм, сохранив текущую SSH-сессию. На 1501 конфигурация допускает TLS 1.0/1.1 — убрать устаревшие протоколы при проверке панели.

## Улучшить перед наполнением и запуском

- **Обновления:** локальный индекс APT показывает 192 обновляемых пакета, включая security-репозитории, OpenSSH, OpenSSL, MySQL, ядро и компоненты панели. Индекс в рамках аудита не обновлялся. Сделать снимок/бэкап, обновить совместимые пакеты и проверить службы. Не менять ветку PHP вслепую; строка 8.3.6 в Ubuntu сама по себе не означает отсутствие backport-исправлений.
- **Резервные копии:** в var/backups сайта только .htaccess; в просмотренных cron нет отдельного задания CS-Cart/бэкапа сайта. Наличие внешних копий Beget/ISPmanager не подтверждено. Нужны копии БД, файлов и конфигураций вне VPS, история версий и пробное восстановление.
- **Кэш:** cache_backend=file; session_backend=database. Redis установлен, но не подключён к CS-Cart. Подключение cache_backend=redis соответствует рекомендации разработчика. Сессии переводить отдельно при необходимости. У Redis сейчас maxmemory=0 и noeviction: перед использованием задать бюджет и продумать политику отдельно для удаляемого кэша и сессий.
- **Долгие операции:** Nginx не задаёт fastcgi_read_timeout — действует стандарт 60 секунд между чтениями, тогда как PHP разрешает 300 секунд выполнения. Возможны 504 при долгой операции без ответа. Согласовать таймаут для нужных операций, добавить slowlog; долгие задачи по возможности выполнять через CLI.
- **Большие формы:** max_input_vars=1000. После установки UniTheme 2 проверить сохранение больших форм и настроек модулей; повышать по требованиям конкретного модуля, например до 3000–5000 при подтверждённой необходимости.
- **Статика:** gzip выключен, специальных правил browser cache для статики нет. Включить сжатие текстовых ресурсов и согласованные Cache-Control для версионированных CSS/JS/изображений. HTML, админку и персональные ответы общим кэшем не покрывать.
- **Права:** config.local.php — 666; var/images/design и каталог AB — 777. Убрать запись для посторонних после проверки владельцев и сценариев обновления. Универсальный chmod для всего сайта не применять.
- **Наблюдаемость:** MySQL slow_query_log выключен; FPM slowlog/status не настроены. Нужны закрытые метрики, контроль 5xx, памяти, диска, сроков сертификатов и резервных копий. Размер пула 30 и память 256M не увеличивать без замеров: одновременно тяжёлые процессы могут занять значительную часть 12 GiB вместе с MySQL и системой.
- **Планировщик:** отдельного cron CS-Cart нет. Проверить реальные требования установленных модулей, импортов и уведомлений; не создавать произвольную cron-команду без проверки dispatch/CLI интерфейса этой версии.
- **БД:** 251 таблица использует utf8mb3_general_ci. Это не препятствует текущему запуску; поддержку четырёхбайтовых символов и миграцию utf8mb4 рассматривать отдельно с учётом CS-Cart и модулей. Автоматическую конверсию не выполнять.

## Ограничения и порядок работы

Не проверялись аутентифицированные сценарии админки, отправка SMTP, загрузка модулей, восстановление копий, внешний firewall Beget и реальная нагрузка после наполнения. Проверка конфигурации FPM отражает разобранные файлы; phpinfo-проверка эффективных параметров живого веб-запроса не проводилась.

Рекомендуемый порядок: защита Nginx и временные каталоги → DNS/HTTPS и закрытие dev → SSH/firewall → бэкапы и обновления → установка UniTheme 2 → Redis, статика и наблюдаемость → функциональные и нагрузочные проверки → перенос URL и запуск.

Не считать пустой disable_functions самостоятельной ошибкой: официальные требования CS-Cart перечисляют exec/system/shell_exec и другие функции как разрешённые. Не отключать AppArmor/другую защиту просто ради общего чеклиста, если нет установленного конфликта приложения.
