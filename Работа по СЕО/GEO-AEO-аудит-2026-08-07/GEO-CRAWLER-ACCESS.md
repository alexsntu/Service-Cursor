## Сводка доступа краулеров

`robots.txt` содержит три явных секции — `User-agent: *`, `User-agent: Google`, `User-agent: Yandex` — идентичные по составу правил (одинаковые `Allow`/`Disallow`). Отдельных директив для AI-краулеров (GPTBot, ClaudeBot, PerplexityBot и др.) нет, поэтому все они подпадают под общую секцию `User-agent: *`, которая **не блокирует** сайт (базовое `Allow: /` + точечные `Disallow` только на служебные разделы — корзина, логин, поиск, кэш, фильтры и т.п.).

## Рекомендации

### Немедленные действия
1. Загрузить `llms.txt` (черновик готов в этой папке) в корень домена — сейчас файл отсутствует, это единственный минус в оценке.
2. Рассмотреть добавление явных `User-agent:`-секций для GPTBot/ClaudeBot/PerplexityBot/Google-Extended в `robots.txt` — не для блокировки, а для явного, документированного разрешения (сейчас доступ есть только "по умолчанию" через `*`, что негласно и может измениться при будущих правках robots.txt, если кто-то добавит блок в `*`-секцию не подумав про AI-ботов).

### Дополнительные технические находки
- **Meta Robots Tags:** `<meta name="robots" content="index, follow">` на главной — ограничений нет.
- **X-Robots-Tag Headers:** отсутствуют — ограничений нет.
- **JavaScript Rendering:** SSR подтверждён — сырой HTML (без выполнения JS) главной страницы и категорийной страницы `/catalog/remont-iphone/` содержит `<title>`, `<h1>`, основной текст, внутренние ссылки (132 шт. на категорийной странице) и JSON-LD (`<script type="application/ld+json">`: 3 блока на главной, 1 на категорийной). Критично для GPTBot/ClaudeBot/PerplexityBot — у них ограниченный JS-рендеринг, а тут контент и так есть в исходном HTML.
- **llms.txt:** отсутствовал на момент аудита (2026-08-07). Черновик подготовлен: `llms.txt` в этой папке — **не выложен на сервер**, требует ручной публикации в корень домена.
- **Sitemap Accessibility:** `sitemap.xml` (HTTP 200) — это sitemap-индекс из 62 под-сайтмапов, преимущественно `.../feed/advanced_sitemap/product&page=N` (постраничный листинг товаров/услуг). Для реального обхода конкретных страниц использовались не эти технические URL, а прямые ссылки на категорийные/сервисные страницы, упомянутые в документации проекта (см. также сверку канонических URL ниже).
- **robots.txt — попутное наблюдение:** помимо стандартных Disallow, в файле есть длинный список из ~90 директив вида `Disallow: /english-word/` (`/abuse/`, `/angel/`, `/heaven/`, `/sword/` и т.д.) — похоже на устаревшую/скопированную защиту от несуществующих путей (возможно, наследие другого шаблона/CMS или защита от спам-ботов по словарю). Не блокирует ничего реального для AI-краулеров, но стоит спросить у того, кто вёл robots.txt, актуальна ли эта секция — вне рамок текущей задачи, просто фиксирую находку.
